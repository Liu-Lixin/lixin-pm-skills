# 询问策略示例集

## 核心原则

- ✅ **结构化提问**: 提供2-4个具体选项，让用户选择
- ❌ **开放式提问**: 避免"您怎么想？"这样的模糊问题
- 💡 **决策树**: 根据用户的回答，逐步深化问题

---

## 场景1: 功能范围定义

### ❌ 开放式提问（避免）
"搜索功能的范围是什么？"

**问题**: 用户可能回答"不知道"或"随便"，导致需求模糊。

### ✅ 结构化提问（推荐）

**问题**: "搜索功能应该覆盖哪些内容？"

**选项**:
- (A) 仅首页功能入口
- (B) 首页功能 + 论坛内容
- (C) 首页功能 + 论坛内容 + 资料库
- (D) 其他（请说明）

**用户选择后的确认**:
> "好的，我理解您的意思是搜索应该覆盖[A/B/C]。这样的话，我们需要在[具体位置]放置搜索框，并且需要与[相关系统]集成。这样理解对吗？"

## 场景2: 优先级确认

### ❌ 开放式提问（避免）
"这个功能的优先级是多少？"

**问题**: 用户可能不理解优先级的含义。

### ✅ 结构化提问（推荐）

**问题**: "这个功能对产品的重要程度如何？"

**选项**:
- (A) P0 - 核心功能，必须在第一版发布
- (B) P1 - 重要功能，应该在第一版发布，但如果时间紧张可以延后
- (C) P2 - 辅助功能，可以在后续版本中添加
- (D) 不确定，需要讨论

**用户选择后的确认**:
> "您认为这是[P0/P1/P2]功能。这意味着[具体含义]。这样理解对吗？"

---

## 场景3: 用户角色定义

### ❌ 开放式提问（避免）
"这个功能的用户是谁？"

**问题**: 用户可能列举很多角色，导致需求复杂化。

### ✅ 结构化提问（推荐）

**问题**: "这个功能的主要用户是谁？"

**选项**:
- (A) 仅新用户
- (B) 仅活跃用户
- (C) 新用户 + 活跃用户
- (D) 所有用户（包括流失用户）

**用户选择后的深化问题**:
> "好的，主要用户是[A/B/C/D]。那么对于[其他用户角色]，他们是否也需要这个功能，还是完全不需要？"

## 场景10: 成本与收益权衡

### ❌ 开放式提问（避免）
"这个功能值得做吗？"

**问题**: 用户可能没有清晰的决策标准。

### ✅ 结构化提问（推荐）

**问题**: "考虑到实现成本和预期收益，您认为这个功能应该如何优先级排序？"

**选项**:
- (A) 高收益、低成本 → P0（必须做）
- (B) 高收益、高成本 → P1（应该做）
- (C) 低收益、低成本 → P2（可以做）
- (D) 低收益、高成本 → 不做（放入后续候选）

**用户选择后的确认**:
> "您认为这个功能是[A/B/C/D]。这意味着我们应该[具体行动]。这样理解对吗？"

## 决策树示例

### 用户故事讨论流程

```
开始
  ↓
问题1: 这个故事涉及UI吗？
  ├─ 是 → 需要ASCII线框图
  │   ↓
  │   问题2: 用户交互方式是什么？
  │   ├─ 单击 → 确认按钮位置和文案
  │   ├─ 滑动 → 确认滑动方向和范围
  │   └─ 其他 → 详细描述
  │
  └─ 否 → 跳过线框图
      ↓
      问题3: 这个故事涉及数据处理吗？
      ├─ 是 → 确认数据来源和处理逻辑
      └─ 否 → 继续下一步
```

## 反模式（要避免的做法）

### ❌ 反模式1: 过度开放
"您还有其他想法吗？"

**问题**: 用户可能给出模糊或不相关的回答。

**改进**: 提供具体的选项或问题。

### ❌ 反模式2: 假设用户知道
"这个功能应该支持多租户吗？"

**问题**: 用户可能不理解"多租户"的含义。

**改进**: 解释概念，然后提供选项。

### ❌ 反模式3: 一次问太多
"这个功能的范围、优先级、用户角色和交互方式是什么？"

**问题**: 用户可能不知道从哪里开始回答。

**改进**: 逐个问题，一次一个。

### ❌ 反模式4: 忽视用户的不确定性
用户说"不知道"，你继续推进。

**问题**: 需求会变得模糊。

**改进**: 提供参考方案或建议，帮助用户做决定。

---

## 最佳实践总结

| 做法 | 示例 | 效果 |
|-----|------|------|
| ✅ 结构化提问 | "您选择A、B还是C？" | 用户快速做决定 |
| ✅ 提供参考 | "常见做法是..." | 用户有参考点 |
| ✅ 确认理解 | "我理解您的意思是..." | 避免误解 |
| ✅ 逐步深化 | 先问范围，再问细节 | 需求逐步清晰 |
| ❌ 开放式提问 | "您怎么想？" | 用户可能不知道 |
| ❌ 假设用户知道 | 使用专业术语不解释 | 用户可能误解 |
| ❌ 一次问太多 | 多个问题混在一起 | 用户不知道怎么回答 |
| ❌ 忽视不确定性 | 用户说"不知道"就继续 | 需求变得模糊 |
